# Security policy

This project processes WhatsApp session data and payment-related evidence. Please handle vulnerability reports privately and do not include credentials, session files, customer data, or unredacted production logs.

## Reporting a vulnerability

Use the repository host's private vulnerability reporting feature when it is enabled. If it is unavailable, contact the maintainers through a private channel listed in the repository owner's profile. Do not report exploitable vulnerabilities in a public issue.

Include the affected component, a concise impact description, and reproducible steps using synthetic data. Redact all tokens, account identifiers, personal information, and production endpoints.

## Scope and response

The maintainers should confirm receipt, assess impact, and coordinate a fix and disclosure with the reporter. No response time or supported-version commitment is implied until maintainers publish one.

## Safe use

Do not test against a live WhatsApp account, Stripe account, customer data, or production deployment unless you have explicit authorization from the system owner. Use isolated test accounts and synthetic receipts.
